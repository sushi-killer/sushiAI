## Orchestrator

- A finished top-level task whose work did not land on its base now gets a pull request from orchd itself, with no help from the overseer and no setting to turn on. This covers a landing refused on the default branch, a task with landing off, and a base checkout that stays dirty for an hour (the landing then gives up, leaves the work on the task branch and tells you). A read-only helper reads the repo's own rules (AGENTS.md, CONTRIBUTING.md, the pull request template) and drafts the branch name, title and body; if it cannot run, the pull request opens with the task's own title and branch. A network or `gh` error is retried (five tries over about 30 minutes). An auth or permanent error sends one notice and the task stays done with `PR: not opened: <reason>`; `task_pr` opens it later. Set `prOnDoneOff` to turn this off, or `prOnDoneRepos` per repo (this replaces the old `prOnDone` switch, which was off by default). `prRoute` picks the drafting route.
- The final commit of a task no longer waits on a signing prompt or an open stdin, and it is stopped after two minutes.
