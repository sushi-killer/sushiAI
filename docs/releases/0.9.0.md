## Routines

- A routine is a scheduled background agent run. Describe it in one sentence. A builder session (Claude Code or Codex) picks the project and host, writes the brief, saves a draft and makes a dry run that writes nothing.
- Each routine runs on its host's daemon by cron (at most every 5 minutes) with its own agent, model and thinking level. A run ends with one JSON result: `noop` is archived quietly, `needs_you` and `failed` go to the Inbox. The app keeps the last 30 runs. Three failed runs in a row pause the routine.
- A routine lists the tools it needs as `access`, and you grant each one. A run uses only granted tools. A routine can also list agent skills (`skills`).
- Run modes: ask every time, ask first (until `promoteAfter` asks were accepted), or on its own. A routine whose files change outside the app is paused until you save it again.
- A routine can work on 0 to 20 projects. With two or more projects it is read-only (Claude only).
- Codex runs use workspace-write with no network and no MCP servers.
- Breaking: the old shell-command routines are removed, with no migration.

## Orchestrator (orchd)

- orchd asks you only about your decisions: scope, a public API, money or an outside service, destructive or security changes. One decider (the overseer, when auto-answer allows it) settles the other questions. A question that parks during quiet hours reaches you when quiet hours end.
- A failing task ends with a report and one notice. It does not wait for an answer. Before this, orchd retries once, changes the approach once, and blames the environment only on a signal it sees itself (a setup failure or a timeout).
- A check that is already red on the base does not stop a task. orchd compares the failing tests with the base and accepts only failures that the base also has. The pull request lists each waived failure.
- Every task branches from a freshly fetched base: the given `base` or the project's default branch. A task that waits for its base fetches it once a minute.
- Planner tests are no longer read-only. When an attempt changes one, orchd restores it. A judge rules on an agent's claim that a planner test is wrong. orchd runs the repo's `format` command (`.sushiai/setup.json`) over planner tests. A `-- check:` must be a runnable shell command.
- A done task that did not land gets a pull request. The branch and title follow the repo's rules. A carry conflict gets one resolution attempt. `prOnDoneOff` and `prOnDoneRepos` replace `prOnDone`.
- `planTimeoutSecs` sets the planner time limit (default 30 minutes).
- The orchestrator MCP can reach every saved host (`host` on task and inbox tools, new `hosts_list`). It also has `task_stop` and `task_delete`. It works only while the app is running.
- You can copy orchd settings between hosts.
- A finished check stops the processes it started. A stopped task stays stopped. Your mark on a just-finished task is kept.

## App and terminal

- Analytics and the "This week" line on Home add up every host of a project.
- Terminal sessions stay responsive under heavy output. Remote input p95 drops from 746 ms to 44 ms (`docs/perf/terminal-sessions.md`).
- Terminal sessions get a UTF-8 locale when the daemon has none (for example, over ssh).
- The New worktree option is available for SSH hosts.
- The test suite no longer stops partway on Node 22.
