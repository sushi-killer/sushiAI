## orchd ends a failing task with a report instead of a question

- A timeout or an install error no longer counts as "the same failure again". A flaky check or a failing test outside the task's diff counts as the environment only when the evidence backs it: the test also fails on the base, or it passed and failed on the same tree.
- "Attempts keep failing" is never an open question now. After the orchestrator's continues (auto-answer only), orchd changes the approach once (a higher tier when the settings define one, and the planner re-plans the rest of the work), then marks the task failed. The owner gets one notice with a report each time the task fails, and the overseer is woken when auto-answer is on. An agent may restart a failed task once; a second restart is refused.
- A review that gives no verdict (or a review run that errors twice) is tried on another route; if none reads the attempt, the attempt is committed and marked unreviewed. It is never landed by itself: the owner gets a pull request whose first line says "Unreviewed" and whose criteria are unchecked. Nobody is asked to approve it.
- Open "attempts keep failing" and "no verdict" questions from before this change are settled when the daemon starts: the first fails the task with its report, the second takes the unreviewed path. The "accept the last attempt as done" option is gone.
- The judge for an impossible criterion runs even after the policy answered three other questions. The policy budget is per kind of question and cause. A dropped criterion names who dropped it, and the report lists it as not done.
- A planner that times out or errors is resumed once with twice the time and a continuation brief before the task fails. A worktree or setup step that fails is tried again twice with a growing pause.
- A dependency that failed on a timeout or an install error is restarted once more by itself after a pause. Dropping a dependency stays the owner's choice.
