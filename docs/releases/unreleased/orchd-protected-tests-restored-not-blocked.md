## Protected tests are restored, not blocked

- orchd no longer makes the planner's tests and the files a task's checks name read-only for the agent, and it no longer raises a permission question for them. An attempt that changes one is not failed: orchd puts the original back, records one decision line, and the next brief tells the agent that its edits were discarded and that the checks run on the originals.
- If the agent thinks a planner test is wrong, it says so in its report (`testClaims`: `path` and `reason`). A fresh read-only judge on the planner route checks the claim against the task goal. Confirmed: the planner rewrites that test, orchd commits it into the planner tests and refreshes the protected hashes, and a decision line records what changed and why. Rejected: the agent carries on. Unclear: one owner question (`Rewrite the test` or `Keep the test`). Each test file is ruled on once per task.
- A document a check names (`.md`, `.mdx`, `.rst`) is no longer protected, so a criterion that asks for a docs change can be met.
- After the task branch is carried onto a moved base, the stored hashes of the files the checks name come from the new head, so a file the new base changed is no longer put back to its old content. A decision line names each file whose hash changed.
- A confirmed rewrite rebuilds the single planner tests commit on the task's base, so the task still lands after the base moves and the agent's own commits are never part of the tests. The rewritten test must still fail on a clean checkout of the base, and a rewrite that drops most of the test's lines is refused. The judge and the planner read a checkout of the tests commit, not the agent's worktree.
- A document is left unprotected only when a check just probes it (`grep`, `rg`, `test`); a document a check compares against, such as a golden file, stays protected.
- In best-of, a candidate whose protected files had to be restored does not count as passed.
- A file the task's own title, goal or criteria name as the thing to change is no longer protected, unless it is a test file or one of the planner's tests. Before each attempt orchd drops such files from the stored protected set of a task an older build prepared, and runs the planner files through the repo's formatter once (recommitting the tests commit) so a test the repo's own format check rejects cannot block the task.
- A tests commit that is no longer the single commit on the task's base (the branch holds more commits, or the base moved through a merge the branch already contains) is rebuilt on the base instead of being skipped forever by the carry. A negated or wrapped probe (`! grep`, `env A=b grep`) still counts as a probe.
