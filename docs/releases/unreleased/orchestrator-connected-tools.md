## Connected tools in the orchestrator chat

- Settings > Orchestration has a CONNECTED TOOLS section: a row per tool with a toggle and a line that says what it gives the chat (for example "Connected · 3 read · 2 ask first") or why it gives nothing. OpenViking, Google Sheets, Slack and Asana are on by default (a missing or signed-out one says why and is skipped); "Add a server from your MCP config…" adds any other server of `~/.claude.json` or an installed Claude Code plugin that is not added yet. Expand a row to overrule whether a tool reads or writes.
- Enabled tools work in Chat, Brainstorm and Plan. Their read tools are available to the orchestrator; a tool that changes something is never callable by it. Instead the reply ends with an OK card (needs your OK, what and where, the tool name, the arguments, Send / Edit / Don't send). Send runs exactly that call once; Edit changes the arguments first; Don't send is recorded and the orchestrator is told on its next turn. The card keeps its state after a reload.
- A server that is missing, needs sign-in or fails never breaks a chat: the turn runs without it and the Settings row says why. On a Codex route only stdio servers are used.
- Nothing secret is stored in orchd's settings: a tool points at its entry in `~/.claude.json` or at the plugin, which is read when a turn starts. Slack reuses the sign-in of the Claude Code Slack plugin; Asana uses Asana's own remote server (`https://mcp.asana.com/v2/mcp`) and needs one sign-in through `/mcp` in Claude Code, because the claude.ai connector cannot be loaded into the chat.
- orchd: settings gain `chatTools`; new `chat.tools` (status and read/write kind of each tool), `chat.toolServers`, `chat.actionSend {repo, messageId, args?}` and `chat.actionDecline {repo, messageId}`. None of them is an MCP tool.
